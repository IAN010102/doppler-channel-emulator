# matlab/ — 自己動手寫 MVDR（五關）＋ 與網頁模擬器對答案

這個資料夾讓你**一步步自己用 MATLAB 寫出 MVDR 波束成形**，再拿網頁模擬器匯出的案例對答案。
不需要任何 MATLAB 工具箱（Toolbox）。

> **MATLAB 部分在開發環境中沒有被執行過**：開發環境沒有 MATLAB，所以這些 `.m` 檔案只做了語法與邏輯的人工檢查；
> 它們與網頁端數據的一致性，只在 Node 端用等價的程式驗證過（`tests/t20_matlab_data.js`：案例資料可重算、
> 批改邏輯對參考解答 5/5、對常見錯誤會判為未通過）。請你在自己的 MATLAB 上跑一遍，若有任何報錯，把畫面貼給助教或開發者。

## 五關進度表

| 關卡 | 檔案（matlab/exercises/） | 做完這一關，你可以對老師或教授說： |
|---|---|---|
| 第 1 關 | `ex1_steering.m` 導向向量 | 「我自己用 MATLAB 算出了天線陣列對某個方向的**導向向量**，和網頁模擬器的數字一樣。」 |
| 第 2 關 | `ex2_covariance.m` 樣本協方差 | 「我自己從天線收到的資料算出了**樣本協方差矩陣**，和網頁模擬器的結果一致。」 |
| 第 3 關 | `ex3_mvdr.m` MVDR 權重 | 「**我自己用 MATLAB 實作了 MVDR，並與網頁模擬器的結果一致。**」 |
| 第 4 關 | `ex4_sinr.m` SINR | 「我知道怎麼用 SINR 評量一組權重好不好，而且我的算法和模擬器的數字吻合。」 |
| 第 5 關 | `ex5_diagload.m` 對角加載 | 「我實作了**對角加載**，並說明快照太少時為什麼需要它，結果與模擬器一致。」 |

## 怎麼開始（用白話說）

1. **先看網頁模擬器**（`index.html`）：把「演算法」選成 SMI，拉一拉「干擾角度」，看波束場型在干擾方向挖了一個洞。MVDR 就是在做這件事。
2. **打開 MATLAB**，把「目前資料夾」切到這個 `matlab/` 資料夾。
3. **一次只做一關，順序是：先自己寫 → 卡住了再看提示 → 最後才看解答。**
   - 打開 `exercises/ex1_steering.m`：檔頭先告訴你這一關要做什麼、生活比喻、輸入輸出、數學式。
   - 在標著 `%%% TODO` 的地方，把問號補成程式（通常只有 2～4 行）。
   - 卡住了，才往下看檔案裡的「【提示】」，**一次只看一條**。
   - 真的寫不出來，才打開 `solutions/ex1_steering_solution.m`（每一行都有白話說明）。
4. **存檔後，在指令視窗輸入 `check_my_work`。** 它會逐關批改：
   - 「通過」：恭喜。
   - 「未通過」：會顯示誤差，以及「最可能的原因」（例如「忘了除以 L」「共軛放錯」「用了 20*log10」）。
   - 「尚未完成」：你還沒填那一關的 `%%% TODO`，**不算失敗**，繼續做就好。
   - 最後一行是「通過 X / 5 關」。
5. 沒填的關卡不會讓程式報錯：它會印出「這一關還沒寫」並回傳 NaN，所以你可以一關一關慢慢來。

小提醒：MATLAB 的單引號 `'` 是**共軛轉置**（不只轉置，還把虛部變號）；`.'` 才是單純轉置。這是最常見的錯誤來源。

## 需要什麼

- MATLAB **R2016b 以上**（要用到 `jsondecode`）。建議 R2020a 以上：較舊的版本讀到中文註解可能出現亂碼（檔案是 UTF-8），
  只影響閱讀，不影響執行。
- 不需要工具箱。
- 檔案在 repo 內的位置：`data/matlab_cases.json`（案例）、`data/curve_*.csv`（曲線），`check_my_work` 與其他腳本會自己找到它們。

## 預期輸出長什麼樣

- `check_my_work`（全部寫對時）：

  ```
  ===== 批改結果（10 個案例）=====
  第 1 關 導向向量 a(θ)  ：通過（最大誤差 3.1e-16）
  第 2 關 樣本協方差 R̂    ：通過（最大誤差 2.4e-16）
  第 3 關 MVDR 權重      ：通過（最大誤差 …e-1x）
  第 4 關 SINR (dB)      ：通過（最大誤差 …e-1x）
  第 5 關 對角加載 MVDR   ：通過（最大誤差 …e-1x）
  通過 5 / 5 關
  ```
  （誤差是 1e-9 以下的很小的數字；具體數字會因 MATLAB 版本略有不同。）

- `verify_cases`：23 個案例 × 6 種演算法 = 138 行，再加上 E0 講義基準的 9 項檢查，每行 `PASS`／`FAIL`，最後是「總共 147 項，通過 N，未通過 M」。
  若有 FAIL，下一行會印出該案例矩陣的條件數 κ(R̂) 與「單純浮點捨入會造成的誤差」估計。**L = N 的案例矩陣可能非常病態（κ 可達 1e8），
  誤差若與該估計同一個數量級，是數值條件的問題，不是公式寫錯**；容許誤差不會被放寬，案例保留在 JSON 裡供你檢查。
- `mc_independent`：一張 40 列的表（訓練模式 × 演算法 × L），最後一行 `比較個數 m = 40，Bonferroni 臨界值 z_crit = …，最大 |z| = …  ->  PASS`。
  這個比對檢驗的是「實作是否符合規格」，不檢驗規格本身。
- `plot_figures`：`figs/` 內出現 fig1～fig4 的 pdf 與 png。

## 失敗時怎麼看

- `check_my_work` 說「未通過」：先看「最可能的原因」那一行；沒有原因時，對照檔頭的【對應數學式】逐項檢查，
  並把每一步的結果用 `size(...)`、`disp(...)` 印出來看大小與數字。先確認第 1、2 關通過，再做第 3～5 關。
- 第 3 關只批改快照數 L 不小於天線數 N 的案例（L < N 時 R̂ 沒有反矩陣，網頁改用「偽逆」，那不是這一關要處理的）。
- 程式報錯：多半是檔案路徑。確認「目前資料夾」是 `matlab/`，且 `data/matlab_cases.json` 存在（在 repo 根目錄執行 `node tests/make_matlab_cases.js` 可重新產生）。
- 想看「怎麼匯出的資料」：`data/README_data.md`。
